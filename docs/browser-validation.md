# 브라우저 검증 기록 — 2026-09-13

## 환경과 범위

- Playwright 1.58.2 + 설치된 Google Chrome의 새 프로필을 사용했다.
- PC 1280×720(한국어), Pixel 7 크기 412×839(영어)를 검사했다. 모바일 실기기나 Safari 검증은 아니다.
- 웹은 `localhost:3100`, 인증·DB는 가상 프로젝트 `demo-yttm-e2e`의 로컬 에뮬레이터를 사용했다. 운영 계정이나 문서는 생성·변경하지 않았다.
- 기본 4개 시나리오는 YouTube 메타데이터/플레이어만 테스트 대역으로 바꾸고, 앱의 실제 로그인 UI·세션 쿠키·영상/메모 저장·지표 API·관리자 집계를 사용했다.
- 별도 실재생 시나리오는 YouTube iframe에 직접 연결했다. 영상 메타데이터만 고정했으며 외부 Google OAuth나 YouTube Data API 호출 성공을 검증한 것은 아니다.

## 발견 및 수정

모바일에서 상단 메뉴가 화면 폭을 넘으면서 브라우저의 시각적 뷰포트와 클릭 위치가 어긋났다. 이 상태에서는 메모 저장 버튼 클릭이 다른 요소에 막혔다. 헤더를 반응형 두 줄 구조로 바꾸고 메뉴 영역의 가로 넘침을 제한했으며, 사용자 메뉴 줄바꿈과 태블릿 뷰어 높이도 맞췄다. 이후 강제 클릭 없이 4개 시나리오가 통과했고, 대시보드·뷰어의 문서 폭이 뷰포트 이내임을 검사했다.

테스트 환경에서는 `next dev --hostname 127.0.0.1`이 next-intl 기본 로케일 rewrite를 다시 네트워크 요청으로 처리해 리다이렉트 루프가 발생했다. 앱의 라우팅 규칙은 변경하지 않고 테스트 서버 주소·hostname을 `localhost`로 통일했다. 한국어는 명시적인 `/ko/login` 진입으로 언어 쿠키를 설정한 뒤 `/login`으로 정규화되는 실제 규칙을 따른다.

## 재실행

```bash
yarn test:e2e
yarn test:e2e:live
yarn playwright show-report playwright-report/standard
yarn playwright show-report playwright-report/live
```

스크린샷과 실패 trace는 `test-results/standard` 및 `test-results/live`에 저장된다. 기본 시나리오는 CI에도 추가했으며, 외부 YouTube 실재생은 수동 실행으로 분리했다.

## 배포 전 남은 확인

실제 Google OAuth 동의 화면, 운영 Firebase 설정·권한, 확장프로그램과 웹 간 계정 연결은 테스트용 인증 에뮬레이터가 대신 확인해 주지 않는다. 배포 환경의 테스트 계정으로 마지막 스모크 검증이 필요하다.
