# 운영 Firestore 읽기 전용 SDK 검증

웹 서버의 Admin SDK 경로와 별개로, 실제 Google 계정의 Firebase 클라이언트 SDK 요청이 운영 규칙을 통과하는지 확인하는 로컬 도구다. 검증용 앱은 운영 웹에 배포하지 않는다.

## 실행

```sh
yarn verify:firestore:live --project yttm-38af5
```

`http://localhost:4318`을 연다. `.env.local`의 공개 Firebase 설정과 명시한 프로젝트가 `yttm-38af5`일 때만 시작한다. 4318 포트가 이미 사용 중이면 기존 프로세스를 임의 종료하지 말고 충돌부터 확인한다.

## 검증 절차

1. 계정 A와 B가 각각 소유한 **기존** 영상의 문서 ID를 입력한다. 두 계정에서 입력한 A/B 대상은 동일해야 한다. YouTube ID나 전체 URL이 아니다.
2. 역할 A를 선택하고 기존 Google 계정 A로 로그인한 뒤 `읽기 전용 검증 실행`을 누른다.
3. 역할 B를 선택하고 기존 Google 계정 B로 로그인한 뒤 같은 검증을 수행한다. 비밀번호·MFA·추가 인증이 필요하면 사용자가 직접 완료한다.
4. 두 계정 각각 9개 항목이 모두 PASS인지 확인한다. 특히 각자 자기 영상의 존재·소유권 확인에 성공해야 상대방의 대상이 존재한다는 양성 대조가 성립한다.
5. 종료 시 `검증 로그인 해제`를 누르고 탭을 닫은 뒤 터미널에서 Ctrl+C로 서버를 중지한다.

하나의 탭에서 두 계정을 순서대로 검증하면 서로 다른 UID와 양쪽 결과를 대조해 전체 통과를 표시한다. **서로 다른 Chrome 프로필에서 검증하면 결과는 공유되지 않는다.** 이 경우 운영자가 동일한 두 대상에 대해 A/B의 결과를 각각 확인해 합산해야 하며, 한쪽 결과만으로 전체 통과를 선언하지 않는다. 대상 입력 변경이나 새로고침은 결과를 초기화한다. 기존 운영 웹 로그인과 로컬 검증 로그인은 별개다.

## 검사 항목과 한계

- 허용: 본인 영상의 존재·UID 일치, 본인 메모 목록, 본인 UID로 필터링한 영상·컬렉션 목록.
- 거부: 타인 영상 직접 조회, 타인 메모 목록, UID 필터 없는 영상·컬렉션 목록, 서버 전용 온보딩 지표 문서 조회.
- 모든 데이터 읽기는 `getDocFromServer`/`getDocsFromServer`를 사용한다. 각 목록은 최대 5개(거부 검사 1개)로 제한한다.
- 거부 검사는 오직 `permission-denied`만 PASS다. 네트워크 오류, 로그인 실패, 조회가 허용된 빈 결과는 PASS가 아니다.
- 영상·메모·컬렉션 쓰기, 소유자 변경, 배치 쓰기, 모든 문서/필드, 공유 토큰 수명주기는 검사하지 않는다. 별도 승인이 필요한 운영 쓰기 테스트를 대체하지 않는다.

## 안전장치

- 서버는 `127.0.0.1:4318`에만 바인딩하고 허용된 Host 헤더만 받는다. GET `/`와 `/probe.js`만 제공한다. 임의 파일 경로·환경변수 파일·POST API는 제공하지 않는다.
- Firebase 공개 설정 중 API key, auth domain, project ID, app ID만 번들에 포함한다. `FIREBASE_ADMIN_SDK`, YouTube API 키 등 서버 비밀값은 포함하지 않는다.
- Firebase Admin SDK나 서비스 계정은 사용하지 않는다. Firestore 쓰기 함수, 인증 토큰 추출·출력, 문서 본문 출력 코드가 없다.
- Firebase 인증은 별도 앱 이름과 `inMemoryPersistence`를 사용하며 이 탭에만 유지한다. Google의 기존 로그인 쿠키 자체를 제거하거나 계정 권한을 변경하지 않는다.
- **기존 Google 계정만 선택한다.** 새 계정을 선택하면 Firebase Auth에 새 사용자가 생성될 수 있으므로 신규 계정 생성 테스트 용도로 사용하지 않는다.
- 새 승인 도메인이나 권한이 필요하다는 오류가 나오면 설정을 자동 변경하지 않고 중단한다.

근거: [Firebase 규칙과 쿼리](https://firebase.google.com/docs/firestore/security/rules-query), [인증 상태 지속성](https://firebase.google.com/docs/auth/web/auth-state-persistence).
